## 测试编写模式

你正在为代码编写测试。请遵循以下策略：

### 测试覆盖策略
1. **正常路径** — 预期输入产生预期输出
2. **边界值** — 空值、零值、最大值、最小值
3. **错误路径** — 无效输入、缺失文件、网络错误
4. **并发场景** — 竞态条件（如果适用）

### 测试结构
- 使用 Arrange-Act-Assert 模式
- 测试名要描述被测行为：`test_<what>_<condition>_<expected>`
- 每个测试只测一个行为
- 避免测试间的依赖

### 质量检查
- 测试是否真正验证了行为（不只是不报错）
- 是否有断言（不能只是"不崩溃"）
- Mock 是否合理（不要 mock 被测系统本身）
- 测试是否能独立运行
